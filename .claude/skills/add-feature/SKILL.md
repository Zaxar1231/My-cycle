# Добавление функции

1. **План.** Если функция больше одного экрана или задевает хранение данных, сначала запусти агента `feature-planner` и согласуй план с пользователем.
2. **Данные.** Данные хранятся только локально. Для структурированных записей используй Room, для настроек — DataStore или SharedPreferences. Сетевых вызовов не добавлять. Если нужна новая зависимость, объясни в PR, зачем она и что она не отправляет данные наружу.
3. **Логика отдельно от UI.** Расчёты (длина цикла, прогноз, фертильное окно) пиши чистыми Kotlin-функциями без Android-зависимостей, чтобы их покрывали JVM-тесты в `app/src/test/`.
4. **UI.** Compose и Material 3, тема из `ui/theme/Theme.kt`. Состояние держи во ViewModel и `StateFlow`. Поддержи тёмную тему и не ломай edge-to-edge.
5. **Строки.** Добавляй каждую строку в оба файла: `res/values/strings.xml` (ru) и `res/values-en/strings.xml` (en).
6. **Тесты.** Логика покрыта unit-тестами, включая граничные случаи: нерегулярный цикл, пропущенные дни, первая запись.
7. **Проверка.** Запусти агента `android-reviewer`, а при изменениях в данных, сети или разрешениях ещё и `privacy-auditor`.
8. **PR.** Заголовок `feat: …` (minor-релиз). Заполни шаблон PR. После push дождись зелёного CI (см. скил `android-ci`).

## Ограничения

- Нет рекламы, аналитики, трекеров, Google Play Services.
- Не обещать точность прогнозов и не позиционировать приложение как контрацепцию.
- minSdk 26: API выше 26 использовать только с проверкой версии.
