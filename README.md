# Twilight Cycle

Нативное Android-приложение для отслеживания менструального цикла с партнёрским режимом, питомцем-маскотом и темами.
**Без рекламы, без трекеров, без Google Play Services** — данные остаются только на устройстве.

## Установка

1. Скачайте [`my-cycle.apk`](https://github.com/Zaxar1231/Twilight-cycle/releases/latest/download/my-cycle.apk) на телефон.
2. Откройте файл и разрешите установку из этого источника, если Android попросит.
3. Дальше приложение обновляется само — повторно скачивать APK не нужно.

Контрольные суммы каждой сборки лежат в `SHA256SUMS.txt` в релизе.

## Обновления

Приложение ищет новые версии в [GitHub Releases](https://github.com/Zaxar1231/Twilight-cycle/releases):

- **автоматически** — при запуске и в фоне раз в 12 часов (WorkManager), с уведомлением о новой версии;
- **по кнопке** «Проверить обновления» в настройках.

Найдя новую версию, приложение показывает описание релиза, скачивает APK с прогресс-баром и открывает системный установщик. Автопроверку можно выключить переключателем.

## Функционал

Разработка идёт по 13 этапам из [ТЗ](docs/spec.md), после каждого выходит релиз.

- [x] **Этап 1.** Модульный каркас, Hilt, навигация (Календарь · Статистика · [+] · Питомец · Настройки), Material You и тёмная тема
- [x] **Этап 2.** Зашифрованная база (Room + SQLCipher), модель данных, онбординг, выбор темы
- [x] **Этап 3.** Прогнозы (`CyclePredictor`: взвешенное среднее, выбросы, фертильное окно, БТТ, уверенность), календарь с фазами, карточка «сегодня»
- [x] **Этап 4.** Запись дня (месячные, обильность, настроение, симптомы, секс, БТТ, вес, препараты, заметка), свой список препаратов, контент по фазам из JSON
- [x] **Этап 5.** Статистика: вкладки Циклы · Записи · Хронология, сводка и закономерности пилюлями, история циклов с полосками дней и правкой, графики длины циклов, БТТ и веса, частота симптомов, настроение по фазам
- [x] **Этап 6.** Гормоны (модельные кривые эстрогена, прогестерона, ЛГ, ФСГ, тестостерона с отметкой «вы здесь»), анализ фаз цикла, вероятность забеременеть на сегодня
- [x] **Этап 7.** Дыхательные практики (4-7-8, квадрат, медленное) с анимированным кругом, таймером и тактильным откликом; аффирмация дня по фазе и настроению из локальных шаблонов (`AffirmationGenerator`), «ещё», избранное, поделиться
- [x] **Этап 8а.** PIN-код из 4 цифр (хранится HMAC с ключом из Android Keystore, после 5 ошибок ввод замораживается), вход по биометрии, автоблокировка после сворачивания, скрытие в недавних, «Забыли PIN?» → биометрия или удаление всех данных
- [x] **Этап 8б.** Главный экран на выбор (Луна, Орбита, Волна, Мозаика, Кольцо) с бóльшими отступами; тема «Свой цвет» с круговой палитрой — вся схема Material 3 строится из одного цвета
- [x] **Этап 8б-2.** Стили Liquid Glass (полупрозрачные карточки над размытыми пятнами цвета, размытие на Android 12+), AMOLED, Пастель, Бумага, Неон; экран PIN в стиле темы
- [x] **Этап 8в.** Шрифт приложения: встроенные Inter, Nunito, Comfortaa, Lora, Caveat (OFL, с кириллицей, вариативные) и свой файл .ttf/.otf
- [x] **Этап 8г.** Кастомизатор главного экрана: порядок (перетаскивание и стрелки), видимость, размер, вид (без фона, заливка, тональная, контур, стекло), скругление углов и цвет каждой плашки
- [x] **Этап 9а.** Аккаунты: вход и регистрация по email и паролю через Supabase Auth (без SDK, сессия зашифрована ключом из Keystore); подключение — [docs/supabase.md](docs/supabase.md)
- [x] **Этап 9б.** Партнёрский режим со сквозным шифрованием: приглашение QR-кодом, ссылкой или кодом (ключ AES-256 только внутри кода), код проверки на обоих телефонах, выбор того, что видит партнёр, экран партнёра с подсказками поддержки, напоминание партнёру перед месячными, отвязка с любой стороны
- [x] **Этап 10а.** Питомец, нарисованный в Compose (котик, лисёнок, зайка, панда, пингвин): дышит, моргает, спит ночью, обнимает грелку во время месячных, грустит вместе с вами; монетки и опыт за записи, дыхание и серии дней; магазин и гардероб из 14 вещей с примеркой
- [x] **Этап 10б.** Общий питомец с партнёром: партнёр видит питомца, кормит его раз в день и дарит вещь раз в неделю; всё зашифровано
- [x] **Этап 11.** Напоминания (скоро месячные, фертильное окно, овуляция, запись дня, препараты) без точных будильников; виджеты: день цикла, дни до месячных и овуляции с полоской цикла, питомец, настроение в одно касание (с PIN-кодом виджеты ничего личного не показывают)
- [x] **Этап 12.** PDF-отчёт для врача, таблица записей в CSV, зашифрованная резервная копия с паролем (PBKDF2 + AES-256-GCM) и восстановление из неё
- [x] **Этап 13.** Полировка, доступность, README

## Как устроены релизы

Всё происходит автоматически:

| Событие | Что делает CI |
| --- | --- |
| Открыт / обновлён PR | [`ci.yml`](.github/workflows/ci.yml): unit-тесты, Android lint, сборка debug APK (лежит в артефактах запуска) |
| PR влит в `main` | [`release.yml`](.github/workflows/release.yml): считает следующую версию, собирает подписанный release APK, создаёт тег и GitHub Release с `my-cycle.apk`, `my-cycle-vX.Y.Z.apk` и `SHA256SUMS.txt` |
| Раз в неделю | Dependabot открывает PR с обновлениями зависимостей и actions; если CI зелёный, PR вливается автоматически и выходит patch-релиз |
| PR из веток `claude/*` (Claude Code) | после зелёного CI вливается автоматически, версия — по заголовку PR. Метка `no-automerge` оставляет PR открытым |

Номер версии определяется заголовком PR / сообщением коммита:

| Заголовок | Версия |
| --- | --- |
| `fix: …`, `chore: …` и любой другой | patch: 0.1.0 → 0.1.1 |
| `feat: …` или `#minor` | minor: 0.1.0 → 0.2.0 |
| `feat!: …`, `BREAKING CHANGE` или `#major` | major: 0.1.0 → 1.0.0 |
| `#norelease` или `[skip release]` | релиз не создаётся |

Первый релиз берёт версию из [`version.properties`](version.properties) (`0.1.0`). Если поднять там `VERSION_NAME` выше последнего тега, будет использовано это значение. Также релиз можно запустить вручную: **Actions → Release → Run workflow** (`auto` = patch).

`versionCode` вычисляется из версии (`1.2.3` → `1002003`), поэтому каждая новая версия ставится поверх старой.

### Подпись релизов

Обновление поверх установленного приложения возможно, только если все релизы подписаны **одним и тем же ключом**. Ключ хранится в секретах репозитория (**Settings → Secrets and variables → Actions**):

| Секрет | Значение |
| --- | --- |
| `SIGNING_KEYSTORE_BASE64` | keystore в base64 (`base64 -w0 release.jks`) |
| `SIGNING_STORE_PASSWORD` | пароль keystore |
| `SIGNING_KEY_ALIAS` | alias ключа |
| `SIGNING_KEY_PASSWORD` | пароль ключа |

Создать свой ключ:

```bash
keytool -genkeypair -v -keystore release.jks -alias mycycle -keyalg RSA -keysize 4096 -validity 10000
base64 -w0 release.jks
```

Храните `release.jks` и пароли в надёжном месте: если ключ потерять, пользователям придётся удалить приложение и поставить заново.

## Сборка локально

Нужны JDK 17+ и Android SDK (проще всего — Android Studio).

```bash
./gradlew test                # unit-тесты всех модулей
./gradlew assembleDebug       # app/build/outputs/apk/debug/app-debug.apk
```

## Технологии

Kotlin · Jetpack Compose · Material 3 · WorkManager · minSdk 26 (Android 8.0) · targetSdk 35

Нет рекламных SDK, аналитики и Google Play Services. Без Firebase: все напоминания создаются на телефоне.

Разрешения:
- **интернет** — проверка обновлений на GitHub и, по желанию, аккаунт и партнёрский режим через ваш собственный проект Supabase;
- **установка пакетов** — самообновление;
- **уведомления** — новые версии и напоминания;
- **биометрия** — по желанию, вход по отпечатку вместо PIN.

Камера не нужна: QR-код приглашения читается обычной камерой телефона.

## Приватность

- Данные хранятся в базе, зашифрованной SQLCipher; ключ базы зашифрован ключом из Android Keystore.
- Облачное резервное копирование Android отключено.
- В партнёрский режим уходят только зашифрованные на телефоне данные: ключ передаётся внутри приглашения, сервер их прочитать не может. Каждый снимок дополняется до одного размера, время изменения не передаётся.
- Резервная копия шифруется паролем и сохраняется туда, куда вы выберете; приложение её никуда не отправляет.
- PDF-отчёт и CSV-таблица не шифруются: их сохраняете вы сами, и прочитать их может любое приложение с доступом к файлу. Заметки и отметки о сексе попадают в CSV, только если вы их включите.
- Если в приложении задан PIN, виджеты на рабочем столе ничего личного не показывают.
- На экране блокировки уведомления можно показывать без подробностей (если в настройках телефона скрыт конфиденциальный контент).

Настройка Supabase для аккаунтов и партнёрского режима — [docs/supabase.md](docs/supabase.md).
